# 教育关系名册阶段交付与证据边界

本阶段继续仓库 P042 教育模型，新增学籍、班级成员、教师任教的学校范围关系目录、分页和详情。不代表 54 表全业务已经完成，不开放姓名、学号、任教学科、变更原因、人员标识或任何写入、删除、身份绑定与状态转换。前一阶段的学校/组织/班级受约束维护保持原样。本阶段依赖教育基础资料 PR，品牌与生成器 PR 仍是独立未合并变更。

## 规则缺口

租户管理员管理本租户学校，学校管理员仅负责学校，均须由真实宿主身份和明确授权支持。新名册用途授权独立于旧基础资料授权，默认不开启。学校目录可展示明确授权但尚无本模块学校执行许可的学校元数据，并标记所有关系操作不可用；不能借此读取该校关系。

管理目的是否允许展示姓名、学号以及 LEFT 历史或 RESTRICTED 人员，尚需产品决定。学期是否只允许 DRAFT 新建和无引用草稿改日期、学期重叠规则、共享自然人改名权限、学籍及任教状态转换同样尚未确定。所谓无引用草稿不能只检查班级，还需要 growth_report 等引用和并发锁协议。未决规则没有在本阶段自动假定。

## 本地证据与待运行

新增 Java 纯边界、真实 JAR 来源解析的独立 Java 检查、源文件/SQL 锁守卫、Python 隔离 fixture/组合计划测试和前端组件检查已本地执行。每次运行报告绑定实际源文件摘要；组件 HTTP 适配器使用显式网络测试替身，不能作为真实登录或数据库验收。实现初次发布时 MySQL、原生 HTTP、真实浏览器和本阶段截图均为 NOT_RUN；只有后续精确提交的 CI artifact 才能将这些范围改为 PASS。

原生验收入口为 `python3 tools/ci_native.py --ingestion --education --roster`。新的 native-education-roster 工作流使用锁定上游、真实 MySQL 8.4、Redis、验证码和加密原生登录，并构建后端 JAR 与双前端。只在本次拥有的随机 fcp_ci_ 空库执行已核对来源和摘要的部署计划；不会对已有库清库、覆盖或执行生产迁移。默认 `--education` 仍只有前一阶段扩展；只有显式 `--roster` 增加本阶段两个 SQL。

先完整执行基础资料 JDBC/HTTP/浏览器，再确认旧基础资料授权不能自动读取新名册，然后单事务加入合成名册数据和独立权限。等待宿主原生限流的完整窗口，不清 Redis、不改限流、不关闭认证。新检查包括学校及租户隔离、学生/教师用途分离、只读白名单、最大 unsigned BIGINT 精确分页、撤权排序、失败拒绝、当前 JAR 摘要绑定和 no-store 响应。所有暂时撤权或坏数据注入都有精确前像、恢复和读取核验。错误摘要启动测试必须真实非零退出且出现固定安全错误标识；超时或无标识不算通过。

真实浏览器仅使用本次合成数据和原生请求，不伪造令牌、不替换响应。截图采用固定 1440×1080 视口与真实滚动，逐帧检查稳定几何，不拼接或重绘。品牌分支尚未组合时，截图不代表最终智慧云校外壳。
