# 系统版本、发布与灰度设计（实施中）

此模块管理系统版本，不管理 Git 分支。源码提交只是构建来源元数据。基线为 dev 1b7b72e；本文是实现目标与验收边界，不构成验收通过声明。

## 分层与可替换契约

版本提供者负责不可变产物、系统版本组合、查询和历史。默认实现与外接 HTTP 协议实现必须执行同一合同测试。系统组合独立绑定宿主后端、管理端 UI、教师端 UI、插件、远程服务、配置和数据库兼容版本；不要求它们使用相同版本号。版本标签不得静默换包，摘要不可变。

发布控制器负责计划、权限、兼容预检、期望状态、实际状态、幂等操作和恢复。部署执行器负责候选部署、健康与实际版本验证、路由切换、排空及回退。提供者必须声明支持的能力，登记一个地址不等于部署成功。外部执行器协议接通不等于已经支持所有云厂商。

灰度路由只接受宿主认证的身份，使用固定策略种子与租户标识稳定分桶。调整比例或策略修订不能让原有成员重新洗牌。排除与紧急停用优先，灰度不授予权限。发布上下文绑定身份、租户和有效期，客户端不能指定任意版本。写请求不得在超时后自动改投另一个版本。

宿主适配负责认证、实时授权、审计与持久化。生产可使用现有 JDBC CAS journal，文件 journal 仅用于单实例开发。控制面重启必须对账未决操作，不盲目重新执行部署。实际状态未确认时不能显示发布成功。

## 实施模块与验收

| 模块 | 交付 | 必须证明 |
|---|---|---|
| 系统版本接口 | 类型模型、默认持久化、外接 HTTP、替换注册 | 不可变性、重启、并发/重复、畸形响应、真实 HTTP 合同 |
| 发布控制面 | 计划、预检、执行、暂停、终止、完成、回退、审计 | CAS、未知结果恢复、实际部署/路由证据、权限与不兼容拒绝 |
| 可信灰度 | 稳定租户分桶、签名亲和上下文、版本端点 | 两个真实服务返回不同版本、扩量稳定、跨租户/伪造拒绝、撤销优先 |
| 宿主与前端 | 原生权限、两套管理视图、可见状态/操作 | 后端拒绝越权、身份切换丢弃旧响应、重复确认与未知结果安全 |
| 全链路扩展 | 宿主 UI 资产、多版本插件、任务与数据兼容 | 两套真实 UI、多版本进程、路由/缓存/在途/崩溃与实际数据库 |

任何未实施或未执行项目必须明确标注，前四模块不能自动代替第五模块。组件用真实 loopback HTTP 只能证明协议和路由，不代表 RuoYi、MySQL、浏览器或生产部署已经通过。

## 关键边界

现有插件生命周期全局只选一个版本；运行时插件灰度需要按插件版本隔离进程、注册、授权摘要、依赖和任务。不得以修改一个全局版本字段替代双版本并存。现有插件包不能直接修改框架和业务源码。

宿主前端构建需不可变资源 URL，认证后的入口清单私有且不可共享缓存，旧资源保留兼容窗口。浏览器已加载的 JS 不会自动变成新版；未保存表单不能被静默清空。控制台界面不等于该资产发布链路。

数据库采用扩展、回填、切换、收缩流程。代码回退不回退已经提交的数据。数据库脏状态、不满足新旧共同兼容窗口必须阻止执行；不自动运行破坏性迁移。业务与审计保留，删除仍为 del=1。

观测缺失、过期、非有限数值、样本不足、业务拒绝和未决写入不能当作健康。暂停扩大流量、停止新请求、排空、取消任务及回退是不同操作。自动放量必须使用真实可靠指标和实际执行结果。
