# Native release-aware task adapter

This optional adapter is an operator-triggered production host integration, not a scheduler or an Exchange compatibility bypass. Deployment supplies an owner-only absolute JSON file through FCP_RELEASE_TASKS_FILE and enables fcp.plugin.release.tasks.enabled. Its format is {"format":1,"tasks":[{"id":"daily-report","tenant":"000000","principal":"daily-report-task","plugin":"reports","capability":"build"}]}. Only fixed tenant scopes are supported. The reserved recovery principal is forbidden. Definitions are loaded once at startup; changing a definition invalidates its prior stored runs rather than rerouting them.

Native authenticated platform release administrators can pin a registered task with a caller-generated run ID and bounded JSON input, then explicitly run that same record. HTTP cannot supply task identity, tenant, scope, command or release affinity. The server creates TASK context from the deployed definition; exact TASK+digest+expiry and platform package approval remain mandatory through the existing version policy. No USER token is persisted, and no admin identity is used to execute plugin code. Disabled tenants and revoked/expired approvals fail live authorization.

The task adapter stores the immutable definition hash, input and run ID before calling the core pin operation. A crash in this gap leaves PINNING and requires operator reconciliation, never implicit retry. Before invoking, a fresh core pin lookup revalidates permission on the pinned version; then EXECUTING is durable. An execution failure or lost completion is UNKNOWN (or remains EXECUTING if persistence fails). These records cannot be run again or assigned a new version by this API. Status and pin responses expose only an explicit control-metadata allowlist, including a separately allowlisted pinned-version summary. They never return stored input, result, input hashes, or nested payload copies, even for COMPLETE or UNKNOWN records. Business results are returned only by run after live authorization, including a final check after successful execution; revoked or expired TASK/package grants block completed-result reads. Exact cancellation of never-started core tasks uses the existing audited release task cancellation endpoint; cancellation is not proof of rollback for UNKNOWN writes.

The adapter uses a single synchronized owner within the native executor's single-JVM deployment boundary and a CAS JDBC journal. Audit records identify the operator and the TASK principal separately. Inputs are private database data and are omitted from status responses and test reports. Application DML-only database privileges are unchanged. No automatic schedule, distributed worker claim, arbitrary remote task identity, or automatic crash reconciliation is claimed.

Acceptance must exercise genuine native login, the JDBC journal and digest grants, real plugin child processes, tenant/principal isolation, pin-before-rollout, drain completion, pending retirement refusal, and revoked task authority. Component tests do not substitute for native acceptance.
