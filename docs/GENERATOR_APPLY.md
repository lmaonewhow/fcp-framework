# 生成代码后直接应用

本模块增强锁定的 RuoYi-Vue-Plus 5.6.2 原生代码生成器。原来的生成方式只下载 `ruoyi.zip`；现在管理端 `/admin/tool/gen` 同时保留“下载”，并提供“生成并应用”。表结构导入、字段编辑与 Velocity 模板仍由真实若依提供，不是另造一套模板或模拟后台。

## 开发工作区配置

此功能默认关闭，必须由部署者在开发环境私有 `fcp-runtime.properties` 中显式配置：

```properties
fcp.generator.enabled=true
fcp.generator.workspace=/absolute/path/to/fcp-source-checkout
```

目录必须是当前 FCP 源码工作区，包含 `AGENTS.md`、`upstreams.lock.json` 与 `tools/native.py`。运行宿主的系统账号需要该目录的写权限。目录不能指向发布 JAR 目录、用户已有数据库或生产部署目录，也不能使用符号链接。不要在生产运行身份下启用源码写入能力。网页不能提交或修改目录。接口额外限制为默认平台租户的原生超级管理员，每次重新核验账号及租户状态，要求显式 Authorization 请求头，并保留原生 `tool:gen:code` 权限检查及操作审计。

浏览器与开发工作区可以位于不同电脑；应用写入的是宿主配置的源码目录，不是浏览器的下载目录。页面不显示系统绝对路径。

## 使用步骤

先按若依原有流程导入业务表，配置包名、类名、模块名和字段。选中至多十张表后点“生成并应用”，查看文件列表及当前/生成内容预览，确认没有冲突后点“确认应用”。每张表最多二百个字段，计划十分钟内有效。重新预览会重新生成一个独立候选，确认时不会偷偷再生成另一份内容。

本轮直接应用支持普通 CRUD 模板，包含业务日期范围查询和以 String 保存逗号分隔值的复选框字段。锁定模板源经过精确校验后修复日期范围类型，并分离复选控件数组与接口字符串，下载和应用使用同一修正后的模板。树形或自定义模板、非 String 复选字段会在生成计划前明确拒绝，仍可使用原下载功能审查；它们没有被计入本轮可直接应用的范围。

直接应用仅支持宿主主数据源，因为原生生成的 Mapper 不含多数据源路由。预览前会读取实际数据库列，检查继承实体必须映射的 `create_dept`、`create_by`、`create_time`、`update_by`、`update_time`；缺列会提前拒绝，避免只编译成功却在查询或写入时失败。这些是必要条件，不替代生成后的业务运行验收。启用多租户时，业务表还需符合宿主的 `tenant_id` 或租户排除配置。

文件自动落入 FCP 的受控源码覆盖层：

| 原生生成文件 | FCP 源码位置 |
| --- | --- |
| `main/java/**` | `integration/ruoyi/src/main/java/**` |
| `main/resources/mapper/**` | `integration/ruoyi/src/main/resources/mapper/**` |
| `vue/api/**` | `integration/plus-ui/src/api/**` |
| `vue/views/**` | `integration/plus-ui/src/views/**` |
| `*Menu.sql` | `generated/sql/*Menu.sql` |

Java、Mapper XML 和管理端 Vue/TypeScript 会被 `tools/native.py` 的正常装配流程读入。后续可以直接在这些源码中做业务调整，不再需要解压 ZIP 后逐文件覆盖。上游或覆盖层存在路径冲突时构建继续明确失败，不会覆盖上游已有代码。

应用源码不等于代码热加载。已运行 JAR 不会改变；接着运行现有类型检查、构建、测试与审查发布流程才会生效。菜单 SQL 仅生成待审文件，不会自动执行，不修改菜单、角色授权或业务数据库。要启用菜单，应经现有数据库迁移/权限审查流程处理。当前原生模板生成的是 plus-ui 页面，不会伪称同时生成 Soybean 教师页面。

## 保留调整与处理冲突

每个文件的基线绑定生成者与原始表编号，不同表生成同一路径时拒绝跨来源覆盖，正常合批或拆批不改变来源。每次成功应用保存上次生成的原始基线。针对锁定若依模板，后续生成沿用基线中的生成日期和菜单编号，避免隔日或重复预览造成伪变更；业务内容或外部父菜单变更仍正常显示。当前文件与基线一致时，新候选可安全更新；生成内容与基线一致但本地文件已修改时，保留手工修改。当前与生成候选两边都改动时，整批计划标为冲突，不写入任何业务源码。首次遇到没有基线的现有不同文件也会冲突；不会把它当作可覆盖的旧生成文件。

冲突时可以查看两侧预览，在自己的源码编辑器审查、合并业务修改后重新生成。系统不猜测业务语义、不提供“强制全部覆盖”。重命名模块、包名或文件时旧文件不会被自动删除，需要按普通源码变更审查；不能把未出现的文件误判为可删除内容。首次接管历史手工复制的生成文件需要单独审查，不会默认覆盖。

计划确认前会重新检查每个目标和基线摘要；预览后有人编辑文件、另一个应用已写入、计划过期或所属用户不符都会拒绝。计划请求只保存在内存中，服务重启后需重新预览；成功操作记录与备份持久保留，相同已成功计划再次确认不会重复写入。

## 撤销与故障恢复

“操作历史与撤销”提供已应用记录和撤销按钮。撤销先检查整批文件是否仍与该操作写入的内容一致，有后续手工修改或新一轮生成时会拒绝，避免用备份覆盖较新的工作。按倒序撤销最近的操作最清晰。它只恢复该操作的源码与生成基线，不回滚数据库，也不撤销已提交或已部署的版本。

写入按文件原子替换，跨进程锁串行协调同一工作区。全部源文件和基线完成后才标记成功。中断时保留操作日志，新的应用会被阻止；重新打开操作历史，对待恢复记录执行“恢复回滚”。网络结果不明时先读取历史和检查工作区，不要假定失败并盲目重复提交。状态目录 `.fcp-generator/` 已被 Git 忽略，应与开发工作区一起备份，不能随意删除，否则既有文件会失去基线保护与恢复证据。

状态空间上限为 256 MiB、最多 256 次操作；达到上限会停止新的应用，历史与撤销仍可用，不会自动删除恢复备份。需要整理时应先由部署者完整备份并审查工作区，不能把清空状态目录当作安全的日常清理。

这不是整个文件系统的多文件事务，也不是对同机恶意进程的安全沙箱。编辑器不遵守应用锁时，应避免在确认落盘的瞬间同时保存相同文件。真实断电、网络文件系统与生产环境未在组件测试中验证。

## 验证证据

`tests/java/GeneratedSourceWorkspaceRegression.java` 使用真实临时文件验证新建、更新、手改保留、冲突整批拒绝、陈旧计划、持久幂等、回滚和故障现场恢复。它不是 Spring/MySQL/浏览器测试。

`tests/generator/native_acceptance.py` 通过 `tools/ci_native.py --ingestion --exchange --generator` 使用真实锁定若依、隔离 MySQL/Redis、原生加密登录和 Chromium，测试原生导入、模板生成、预览、点击确认、真实落盘、手改、冲突、陈旧计划、UI 撤销及越权拒绝，并对生成后的 Java 与管理端源码执行真实编译/构建/类型检查。此测试不执行生成菜单 SQL，不声明生成业务已经上线。结果写到 `reports/generator-native/acceptance.json`，构建及源码标识绑定该次实际运行。测试代码存在不表示验收通过，应查看对应提交 CI 的真实结果。

进一步的生成业务运行验收使用显式的 `--generator-business`，同时要求 `--generator --ingestion`。它仅能操作本次创建的隔离 CI 测试库，在菜单 SQL 预检、输出计划和保存备份之后安装合成业务的菜单及测试权限，将实际生成并应用的源码重新打包到真实若依 JAR，再运行浏览器业务操作和截图。原生成器的“确认应用”仍然只写源码，不执行 SQL，也不会因此获得部署权限。生成业务的运行结论、截图、实际覆盖范围和未运行项以该次报告为准，不能由源文件存在或编译成功推断。
