# FCP 0.5.0-dev.1 实施与验收报告

日期：2026 年 11 月 1 日。当前成果为生产化基础实现与候选源码，**真实若依完整集成和生产发布状态仍为 BLOCKED**。本轮没有原生应用运行 JAR、真实 MySQL 通过结果、原生双前端录屏或原生性能数字。源代码在独立分支 `feat/production-hardening-0.5.0` 修改；本轮没有推送远程仓库、创建云资源或执行 CI。

## 本轮实际修复与实现

从交付的 0.4.2 源码继续，而非重新制作参考后台。通过固定上游源码确认真正入口是 `org.dromara.DromaraApplication`，修正上一版的错误类名，加入完整源码夹具和 Git blob 校验。Maven 改用生产 profile，显式要求执行测试，并解析 Surefire/Failsafe 报告。没有测试报告不能算上游测试通过。两个原生前端的上游版本与既有集成结构保留，运行目标仍为一条 Java 命令提供两套预构建界面和后端。

新增插件状态 SPI、受限内存实现、持久化文件实现及原生宿主 JDBC 实现。插件期望状态有版本号，更新采用比较并交换，管理操作在持久化前重新授权；原生统计插件首次默认停用。已有停用状态重启后保留，旧页面版本不能覆盖新状态。运行时发布失败时保留可检查的期望状态，后续请求重新核对，不虚构成功回滚。租户运行快照有容量上限，读调用保留并发，启停等待本节点在途调用完成。

新增基于原生数据库结构的 FCP 授权解析：有效用户、租户状态与有效期、角色、菜单、租户套餐及班级范围从数据库查询。用户和租户来自宿主登录会话，不能用请求参数冒充。FCP 写入前再次授权，管理更新前再次核对身份。该行为只约束 FCP 能力边界，未替换整个若依授权体系；新增权限可能仍需刷新原生会话。超级管理员也需显式分配 FCP 管理角色。

新增 V003 状态/审计表和独立增量迁移工具。JDBC 启停状态与审计记录在同一事务中提交，冲突拒绝，无法确定提交结果时丢弃连接并要求刷新。迁移工具默认仅生成计划，明确批准计划摘要后执行；检查历史版本、脚本校验和和脏状态，使用独立部署凭证及命名锁。运行账号没有 DDL 入口，失败不会自动重建生产库或删除数据。真实 MySQL 执行仍未完成。

新增生产目标配置和严格发布门禁。构建、权限、浏览器、迁移、混合负载、24 小时稳定性、安全、恢复及基线证据必须对应同一构建、JAR 和验收目标；原始附件校验摘要、范围和格式，视频必须可解码。门禁验证证据一致性，不能替代可信执行器和独立审查。仅将 JSON 写成 PASS 不会成为真实验收证据。

新增手动 GitHub Actions 工作流与隔离 CI 编排。代码准备在独立 MySQL/Redis 服务中完成上游构建、真实 JDBC 适配器测试和 Java 静态入口冒烟。工作流尚未推送或运行。它的成功范围也不包含全部真实账号、浏览器、负载、安全或恢复验收。

## 真实发现的锁缺陷

跨 JVM 测试确实发现了持久化文件锁缺陷：同一 JVM 中第二次打开失败后，关闭第二个文件描述符可能释放原持有进程的锁，使另一个 JVM 进入。修复为在打开第二个描述符前按文件身份进行 JVM 内占用登记，并保留跨 JVM 探针测试。首次失败输出在 `reports/history/cross-jvm-lock-first-failure.log`。修复后再次测试，同 JVM 重复打开和不同 JVM 并发写均被拒绝。此文件实现仍限已验证的 Linux 单机环境；原生若依使用 JDBC 实现。
