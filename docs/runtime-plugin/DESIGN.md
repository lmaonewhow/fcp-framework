# FCP 运行时插件框架技术设计与验收清单

版本：设计草案 1.1。范围：根据已确认选择形成实现依据，不修改仓库，不执行迁移或部署。

本次修订：追加两套既有前端的固定适配与可复用接入契约；保留原有运行时、安全、存储及分阶段边界。新增内容是设计目标，不代表适配已完成。

## 1 结论与阅读方式

FCP 的核心目标是让宿主通过稳定契约接入运行时插件，管理员可以安装、授权、启用、停用和升级插件，而不让插件修改宿主或业务源码。跨语言通过进程间或网络协议实现；动态生效通过运行时注册、路由、权限和生命周期治理实现。微服务解决部署与通信，FCP 补充面向产品的插件治理，两者可以组合。

首期以 RuoYi-Vue-Plus 5.6.2 为真实宿主，交付单实例、本地独立进程、配置式前端、独立插件数据、学生名单导入导出闭环。为远程服务和其他宿主保留明确接口，不把预留接口宣称为已支持。

本文使用三种标识：
- **既有事实**：来自交接的固定提交审查结果，未在本次重新运行测试。
- **已确认要求**：用户已确认的行为边界和阶段选择。
- **设计建议**：为实现上述要求提出的接口、表名、状态机和实现顺序，尚未落地。

任何“应”“必须”和验收条目均描述目标，不代表代码已实现。性能、稳定性、安全隔离和多实例一致性需要实际验证。

## 2 已确认的范围与决策

### 2.1 当前已确认的基本边界

1. 插件通过获准端点、能力接口、前端预留槽位和受控存储工作，不直接修改业务系统或框架源码。
2. 插件数据先独立归属。首期可共用物理数据库，但不能因此共享表访问权；以后按场景支持独立数据库与受控业务数据关联。
3. 简单数据使用通用存储，复杂业务使用插件声明的专属结构；结构变更由 FCP 校验、执行和审计。
4. 插件只拿到 FCP 存储接口，不获得直连数据库凭据。停用和卸载不删除数据；明确的数据删除操作使用 del=1，不硬删除。
5. 插件声明能力需求，管理员授权。用户请求同时受插件授权、用户权限和租户范围约束。
6. 自动任务使用单独授权的任务身份，不借用管理员全部权限。
7. 停用首先拒绝新工作，等待在途工作完成；超时由管理员选择继续等或受控取消，不能声称撤销已经提交的业务效果。
8. 首期只接纳可信开发者的插件包，但仍需要包校验、最小权限和操作审计。
9. 本地独立进程先实现；远程服务随后接入。跨语言不意味着同进程加载任何语言。
10. 前端先配置式页面和预留槽位，复杂开发式页面后续扩展；没有确认首期实现拖拽页面编辑器。
11. 依赖插件采用展示依赖图、展示新增权限、管理员确认后联合启用；缺失、冲突或未授权不能自动绕过。

### 2.2 本轮确认的十二项补充

| 项目 | 已确认选择 |

1. 对现有 plus-ui 和 soybean 两套前端分别做固定改造，形成可维护的 FCP 适配实现，保留原有 UI 与业务使用方式。

## 4 分层与依赖规则

建议划分以下层级，名称可按仓库惯例调整，不要求立即重排所有目录。

1. **契约层 contracts**：插件清单、能力描述、请求响应、事件、存储和 UI Schema。核心定义不引用 Spring、RuoYi 实体或前端 UI 框架类型。
2. **控制层 control plane**：安装目录、授权、租户启用、依赖图、操作日志、版本发布、恢复协调器。负责决定“应该运行什么”。
3. **执行层 runtime**：调用准入、路由快照、本地进程 Provider、远程 Provider、健康与在途任务。负责确认“现在能调用什么”。
4. **宿主能力层 host capabilities**：身份、租户、授权、日志、存储、任务、文件等标准端口。宿主适配器把既有框架能力映射进来。
5. **业务与插件层**：学生名单、模拟考试及连接器、格式适配器。业务规则由业务模块维护，不塞进核心。
6. **前端壳层**：认证导航、页面注册、槽位渲染、配置组件、操作状态和错误处理。

核心只依赖契约和端口，不依赖 RuoYi。RuoYi 适配器可以依赖 RuoYi。插件依赖契约 SDK，不依赖 FCP 内部实现。配置只能选择声明过的能力，不允许通过类名、脚本表达式或任意 URL 获得额外访问。

同一规范不等于所有模块必须同一种通信方式。嵌入式 Java 宿主可使用内存接口；跨进程宿主适配使用版本化协议。两条路径必须通过同一套契约一致性测试。

## 5 完整契约的最小集合

### 5.1 插件清单

建议 plugin.json 至少包含：
- pluginId、version、manifestVersion、发布者标识、内容摘要与可信发布信息。
- 所需 FCP 契约版本范围、宿主能力及版本范围、插件依赖范围。
- 提供与请求的能力：操作标识、输入输出 Schema、权限标识、是否有副作用、幂等支持、超时策略。
- runtime：本地进程或远程引用；本地入口必须位于校验后的包内，参数按数组传递，不拼 shell 字符串。
- storage：结构版本、声明式表/字段/索引、迁移计划、兼容版本范围。
- ui：页面、槽位、组件、输入配置、能力绑定、权限和契约版本。
- 自动任务模板、配置 Schema、秘密引用的名称，不包含明文秘密。
- 生命周期策略：是否可排空、取消协议、升级模式、健康检查及就绪条件。

字段未知、契约主版本不兼容、重复标识、越权槽位、循环依赖应在启用前拒绝。签名只能证明来源和完整性，不能证明插件行为安全。

### 5.2 调用上下文

可信调用上下文由 FCP 构造：requestId、traceId、pluginId、插件版本、运行实例、tenantId、用户或任务身份引用、授权版本、发布 generation、deadline、幂等键。用户可以提交业务对象 ID，但不能自己决定可信租户和身份。

响应包含 result 或稳定错误码、requestId、可否重试、提交结果是否已知。建议错误类别：INVALID_ARGUMENT、PERMISSION_DENIED、PLUGIN_DISABLED、DEPENDENCY_UNAVAILABLE、VERSION_CONFLICT、DEADLINE_EXCEEDED、CANCELLED、OUTCOME_UNKNOWN、INTERNAL_ERROR。外部响应不泄漏凭据、SQL 或内部堆栈。

幂等键不能成为越权复用入口，至少绑定租户、插件、操作和调用身份范围，并核对请求摘要。重试策略不能对未知副作用一律自动重试。

### 5.3 本地进程协议

复用现有 JSON-RPC 2.0 与 fcp.call，但补充 handshake、ready、invoke、cancel、drain、shutdown、health 的明确语义和版本协商。标准输出只允许协议消息，日志走标准错误或专用日志通道；限制帧大小、并发、响应等待和队列长度。

本地插件不得要求读取宿主环境里的全部秘密。运行器只注入允许配置及短期能力引用。控制层和运行器记录 PID、实例 ID、启动时间和控制凭证，不能仅凭 PID 清理进程，以免误杀复用 PID。

### 5.4 宿主契约

最低必要能力：验证身份、解析租户与组织范围、检查权限、审计、受控存储、配置/秘密引用、时间与任务调度端口。文件、通知、业务流程和监控等通过能力描述按需声明。

宿主注册包含 hostId、实现与契约版本、部署拓扑引用、能力清单、健康、信任配置。所谓“任意框架接入”是该框架可实现这些接口并通过一致性测试，不是任意框架零适配即兼容。

远程宿主模式还需要独立控制面部署与网络身份，首期嵌入式 RuoYi 不自动拥有该能力。第二宿主验收前，仅可称“契约已预留”。

### 5.5 管理 API 与能力协议建议

以下路径均为设计建议，不代表现有端点。所有管理写操作要求宿主认证、目标范围权限、审计，并对适用的浏览器会话实施 CSRF 防护。

| 接口 | 请求要点 | 返回与约束 |
| --- | --- | --- |
| POST /fcp/packages | 包文件、摘要、幂等键 | 上传/校验操作 ID，不直接执行包 |
| GET /fcp/packages/{pluginId}/versions | 插件标识 | 可安装版本、验证结果、兼容要求 |
| POST /fcp/plugins/{pluginId}/plans | enable/disable/upgrade/uninstall、scope、目标版本、expectedRevision | 依赖与影响图、权限差异、迁移计划、planId、内容摘要 |
| POST /fcp/plans/{planId}/confirm | 计划摘要、幂等键 | operationId；权限或依赖变更使旧计划失效 |
| GET /fcp/operations/{operationId} | 操作标识 | 持久阶段、实际生效状态、错误、允许的后续动作 |
| POST /fcp/operations/{operationId}/decision | 排空超时后的 wait/cancel 等允许动作 | 校验当前阶段和 revision，不接受任意状态跳转 |
| GET /fcp/plugins | 当前授权范围、分页条件 | 安装、期望、运行、有效状态分别返回 |
| GET /fcp/ui/catalog | 租户与用户由认证解析、已知 revision | 当前可见页面/槽位及 revision，可使用 ETag |
| POST /fcp/capabilities/{capabilityId}/invoke | 业务输入、幂等键、截止时间建议 | 校验可信上下文后调用，不信任前端传入主体 |
| POST /fcp/exchange/jobs | 业务类型、输入引用、配置版本 | 任务 ID；人工请求进入预览流程 |
| POST /fcp/exchange/jobs/{jobId}/confirm | 预览摘要、已允许冲突策略、expectedRevision | 重验权限与输入版本后提交，返回任务状态 |
| GET /fcp/exchange/jobs/{jobId} | 任务标识 | 进度、各类计数、冲突与结果引用，按范围过滤 |
| GET /fcp/exports/{exportId}/download | 导出标识 | 重新鉴权后的下载，不把存储私有 URL 当公开权限 |

长操作返回 202 与 operationId，不让 HTTP 超时掩盖后台已执行。客户端断线不等于取消。计划确认绑定内容摘要和依赖/授权版本，避免“确认的是 A，执行成了 B”。管理 API 与插件能力 RPC 分开；插件不能经 fcp.call 调用平台安装或授权管理接口。

能力 SDK 应覆盖身份只读上下文、声明能力调用、受控存储、受控文件、任务进度与取消观察；所有操作都绑定当前运行实例和服务端授予的作用域。限制递归依赖调用的深度和预算，防止 fcp.call 形成无界调用环。

## 6 生命周期与作用域状态

必须分开四类状态，避免一个 enabled 字段承担全部职责：
- 安装版本：STAGED → VERIFIED → INSTALLED；失败为 FAILED；卸载后保留历史元数据。
- 部署实例：STARTING → READY → DRAINING → STOPPED，异常为 FAILED/UNKNOWN。
- 租户期望状态：ENABLED 或 DISABLED，附 revision 与所选版本策略。
- 有效状态：综合安装、授权、依赖、迁移、就绪、租户范围计算 READY/BLOCKED/DRAINING/DISABLED。

首期建议平台统一选择一个活动插件版本，租户独立启用。不同租户并行运行不同版本不是本轮既定范围，需以后独立设计路由、结构兼容和资源成本。

进程共享策略也不是“独立数据”的必然结论。建议可信插件首期按部署实例复用进程、每请求携带不可伪造的租户上下文，存储服务强制隔离；需要强隔离的插件可选每租户实例。若插件能在同进程中保留多个租户数据，应明确这不是对恶意插件的强租户沙箱。

### 启用

校验包和版本 → 计算依赖闭包 → 展示权限与影响 → 管理员确认 → 记录操作 → 校验迁移状态 → 启动并健康检查 → 发布新路由快照 → 生效并审计。失败不得留下可调用但未授权的半成品；可恢复资源按操作记录回收或重试。

### 停用

确认级联影响和操作者权限 → 禁止新调度与新入口 → 发布准入拒绝版本 → 排空在途 → 移除页面可用入口与槽位 → 停止无其他使用者的本地实例 → 标记完成。租户停用不停止其他租户共享实例。远程注册服务只撤销调用，不默认操作其进程。

排空允许的是已接纳工作的受控完成，不是继续接收派生无限工作。任务执行中的能力调用仍校验授权；安全撤权优先于优雅排空。取消只承诺发出取消和记录结果，不能保证任意外部系统已撤销操作。

### 卸载和恢复

卸载先停用、检查依赖与任务，再移除可执行安装引用；业务数据、结构版本和审计保留。不在卸载时自动设置业务数据 del=1。显式删除数据才设置 del=1；重装先做结构兼容检查，不能默认将所有删除数据恢复。

## 7 并发与崩溃恢复

### 7.1 一致性边界

数据库、文件系统、插件进程、远程服务不能组成一个普通数据库事务。设计采用持久操作日志、不可变包、版本化快照和恢复协调器，不宣称全局原子事务或恰好一次执行。

建议操作记录包含 operationId、幂等键、目标、期望 revision、目标 generation、阶段、执行节点、错误、开始时间、心跳和结果。每次有外部副作用之前先写可恢复意图，完成后持久化观测结果。

首期每个插件的变更串行协调，数据库 revision 比较更新防止并发启停/升级覆盖；多个依赖按固定顺序取锁并重新验证依赖图，避免死锁。锁失败返回明确冲突，不自动覆盖管理员另一个选择。

### 7.2 发布提交点

1. 包下载/上传进入不可执行暂存区，验证路径、解压大小、摘要和来源。
2. 生成不可变的已验证目录；同文件系统 rename 可用于目录发布，但不能代替数据库事务。
3. 在操作日志记录准备版本，完成必要迁移和进程就绪检查。
4. 数据库以 CAS 更新期望活动 generation 和发布描述。
5. 运行时原子替换当前路由快照，记录已应用 generation，再宣布当前节点生效。

步骤 4 和 5 之间崩溃后，由启动协调器按持久意图恢复，不得误报操作完成。首期只有单节点调用入口；即使如此，也应返回“处理中”直到运行时确认。多实例将来需要广播、节点回执、栅栏拒绝旧 generation 及故障节点退出，不由单节点方案自动获得。

在途请求持有原快照引用直到完成；新请求只进入当前可用快照。数据库写入与状态性副作用必要时校验有效授权/代际栅栏，避免停用后旧任务继续产生新业务。旧请求允许完成的边界必须按具体操作定义，不能通过持有快照绕过撤权。

### 7.3 恢复规则

- 已落盘未登记的暂存包：列为未引用资源，可在明确临时文件保留策略后清理；不连带删除业务数据。
- 已登记未启动：恢复启动或标记失败，不能标记 READY。
- 已启动未发布：校验实例身份和健康，继续发布或停止孤立实例。
- 已发布但数据库回执未写：比较 generation，幂等补写回执。
- 数据已提交但进程响应丢失：依赖幂等记录查询；无法确定时 OUTCOME_UNKNOWN，人工核对或业务补偿，不盲重放。
- 插件崩溃：摘除就绪、拒绝新调用、标记在途结果；重启预算与退避需配置，防止无限崩溃循环。
- 主机重启：首先恢复迁移/操作，再建立运行快照；用户只看到实际可用状态，不把历史 enabled 当作已启动。

## 8 数据存储与迁移

### 8.1 受控存储接口

提供 collection/schema 注册、读写、分页、事务、版本比较、逻辑删除等操作。查询使用结构化条件表达式，不接受任意 SQL、表名拼接或任意函数。服务端注入 pluginId、tenantId、数据域、del=0 和权限范围，并限制字段、排序、分页、查询成本。

复杂插件表可包含专属字段，但必须注册所有权和 Schema，通用存储服务按批准结构访问。跨插件读写只能调用对方授权的业务能力，不共享表凭据；业务模块可通过受控领域 API 提供必要关联。

显式删除需明确范围，设置 del=1 并记录操作者、时间和请求。逻辑删除不等于数据不可恢复，也不是符合所有隐私法规的永久抹除方案；若以后有依法彻底删除要求，应单独确认产品政策，不能自行改变本轮约定。

### 8.2 迁移执行

插件提交声明式变更计划，FCP 生成数据库方言 SQL 并校验：所有权、命名、范围、兼容性、索引影响和执行前置条件。首期支持新增表、新增可空字段、经检查的索引等兼容迁移；删除列、缩窄类型、改业务含义不能自动执行。

MySQL DDL 可能隐式提交，不能承诺整个迁移批次回滚。每步记录 checksum、开始/完成/失败、前后结构摘要，恢复时读取真实结构后决定继续或停止。数据回填要有游标、限流和可重入规则。失败时不把新插件置 READY。

代码回滚与数据库回滚分开：新版迁移后只允许回退到声明且验证兼容当前结构的旧版本；无法证明兼容则保持停用，进行前向修复或经验证的备份恢复。备份恢复必须考虑同库其他插件，不能为一个插件回滚整库覆盖其他业务。

### 8.3 表设计建议

下列是建议表，不是当前仓库已存在表，最终命名、字段类型和索引需结合 MySQL 版本、现有迁移框架确认。

| 表 | 核心字段和职责 |
| --- | --- |
| fcp_plugin_package | plugin_id、version、digest、manifest、install_state；不可变版本包 |
| fcp_plugin_scope | plugin_id、scope_kind、scope_id、desired_state、revision；全局与租户期望 |
| fcp_plugin_release | plugin_id、generation、version、state、revision；活动发布引用 |
| fcp_plugin_instance | instance_id、plugin_id、version、node_id、health、applied_generation；运行实例 |
| fcp_plugin_operation | operation_id、idempotency_key、phase、expected_revision、target_generation、result；可恢复操作 |
| fcp_plugin_grant | plugin_id、主体范围、能力与动作、授权版本、生效及撤销信息 |
| fcp_plugin_dependency | 版本依赖边、兼容范围；构建依赖闭包和反向影响 |
| fcp_plugin_schema | plugin_id、结构标识、结构版本、所有权、摘要 |
| fcp_plugin_migration | 结构版本、步骤、checksum、状态、错误；迁移检查点 |
| fcp_plugin_record | tenant_id、plugin_id、collection、record_id、body、revision、del；简单通用存储 |
| fcp_exchange_job | 租户、插件、配置版本、身份引用、输入摘要、状态、检查点、计数 |
| fcp_exchange_item | job_id、行号或源键、校验与冲突结果、提交状态；按业务量决定明细保留策略 |
| fcp_task_identity | 授权主体、租户范围、能力集、有效期、撤销状态，不存明文凭据 |
| fcp_outbox | 同库提交后的待发布事件，消费者仍需去重 |

示意 DDL 如下，仅表达约束，不可直接作为完整生产迁移运行：

```sql
CREATE TABLE fcp_plugin_scope (
  id BIGINT NOT NULL PRIMARY KEY,
  plugin_id VARCHAR(128) NOT NULL,
  scope_kind VARCHAR(16) NOT NULL,
  scope_id VARCHAR(128) NOT NULL,
  desired_state VARCHAR(16) NOT NULL,
  revision BIGINT NOT NULL DEFAULT 0,
  updated_at DATETIME(6) NOT NULL,
  UNIQUE KEY uk_plugin_scope (plugin_id, scope_kind, scope_id)
);

CREATE TABLE fcp_plugin_operation (
  operation_id VARCHAR(64) NOT NULL PRIMARY KEY,
  plugin_id VARCHAR(128) NOT NULL,
  idempotency_key VARCHAR(128) NOT NULL,
  request_digest CHAR(64) NOT NULL,
  operation_type VARCHAR(32) NOT NULL,
  phase VARCHAR(32) NOT NULL,
  expected_revision BIGINT NOT NULL,
  target_generation BIGINT NULL,
  result_json JSON NULL,
  created_at DATETIME(6) NOT NULL,
  updated_at DATETIME(6) NOT NULL,
  UNIQUE KEY uk_operation_retry (plugin_id, idempotency_key)
);

CREATE TABLE fcp_plugin_record (
  record_id VARCHAR(64) NOT NULL PRIMARY KEY,
  tenant_id VARCHAR(128) NOT NULL,
  plugin_id VARCHAR(128) NOT NULL,
  collection_name VARCHAR(128) NOT NULL,
  body JSON NOT NULL,
  revision BIGINT NOT NULL DEFAULT 0,
  del TINYINT NOT NULL DEFAULT 0,
  created_at DATETIME(6) NOT NULL,
  updated_at DATETIME(6) NOT NULL,
  KEY ix_record_scope (tenant_id, plugin_id, collection_name, del)
);
```

逻辑删除下不能简单假设 UNIQUE(tenant_id,business_key,del) 足以保存任意数量历史删除记录。可按业务采用单独活动键占用表，或支持的数据库版本下采用删除后为 NULL 的活动键索引；需要验证重复删除、重新导入和恢复冲突。学生唯一标识与冲突规则由学生领域契约明确，不用姓名擅自推断唯一性。

## 9 权限与安全边界

请求准入同时满足：安装可信、租户启用、实例就绪、依赖就绪、插件能力授权、调用身份权限、租户/组织数据范围、请求与存储 Schema。UI 隐藏只是体验，所有限制在服务端执行。

平台安装者、平台授权者、租户管理员、业务操作员、自动任务身份是不同角色，可由宿主 RBAC 映射。级联启停涉及每个目标的授权检查，不能只检查入口插件。

自动任务保存固定配置版本和身份授权引用，执行时重新确认权限有效；授权被撤销或租户停用立即阻止后续启动。用户预览后授权变化时，提交必须重新验证。

包安装检查路径穿越、符号链接、绝对路径、解压炸弹、覆盖冲突、未知入口、摘要与大小。包的执行目录、上传区和业务文件区分离。记录来源、版本、授权人及验证结果。

独立进程若与宿主使用同一 OS 用户，仍可能读取宿主文件、环境或访问网络。应用层“不提供 DB 凭据”不能保证恶意代码不可获取凭据。首期可信插件必须明确该信任假设；强隔离需要独立 OS 身份或容器、文件与网络边界，并实际验证。不要在没有隔离措施时声称任意上传包安全。

## 10 前端可插拔

### 10.1 配置页面与槽位边界

前端壳提供版本化 page/slot/component 协议。页面清单指定命名空间内路径、标题、权限、布局与配置；槽位清单指定 slotId、允许组件类别、输入输出 Schema 和排序规则。宿主先声明槽位，插件不能创建对任意 DOM 的访问权。

首期只渲染白名单组件，不 eval、不加载任意用户脚本、不允许任意 HTML。数据源通过 capabilityId 绑定受控调用，而不是允许插件配置任意带凭据的 URL。完整新页面不等于执行任意前端代码。

启用完成后发布 UI catalog revision；壳层通过版本轮询或已认证推送获取更新，具体通道可复用宿主 SSE。首次进入和刷新均重新获取当前清单。服务端停用即时拒绝调用，浏览器更新晚到也不能继续操作。

停用时清理导航、槽位、订阅与组件资源。正在编辑的页面提示未保存内容，允许复制或暂存经批准的数据，但不能因未保存表单阻止服务端安全停用；表单不能在插件停用后绕过服务端提交。前端遇到组件版本不兼容应展示明确错误，不拖垮整个壳。

后续开发式页面需要另行选择隔离方案、资源加载与兼容协议。不能直接把远程 JS 挂到宿主全权限上下文后称为安全插件。

### 10.2 现有两套前端的适配基线

**既有事实**：固定提交下，plus-ui 与 soybean 已有各自的 transport 适配，分别处理 `{code,msg,data}` 与 `{data,error}` 包装。共享 bridge 仍面向 `/fcp/school` 与 school 调用上下文；useSchool 使用 Vue 响应式与生命周期。它们是可复用的起点，不是已经完成的通用 UI 适配 SDK。

当前 session 逻辑面向同源、可信的 admin/teacher 两个壳，并使用 `FCP-Host-Token`。soybean 路由映射到预编译的 school、ingestion 页面；native.py 在构建时合入共享代码和两套前端资源，并适配入口、认证、路由、国际化及环境配置。因此，“动态返回菜单/路由”不能等同于“任意新插件页面已经可以热加载”。现有令牌共享方式也不能直接推广到第三方页面或跨域插件。

**已确认要求的落地目标**：分别维护 plus-ui 适配器与 soybean 适配器。每个适配器固定支持的上游版本、改造位置与契约版本；上游升级时通过差异检查和回归测试更新，不承诺无条件自动兼容。

### 10.3 宿主适配与业务分离

**设计建议**：前端按以下职责拆分，目录名称可沿用项目惯例。

- **宿主 UI**：保留自身登录页、布局、导航容器、主题及既有业务页面，提供获准槽位，不由插件重写。
- **FCP 通用前端协议与客户端**：维护框架无关的页面/槽位 Schema、能力调用数据、版本、错误和事件协议，不依赖 Vue/React、宿主 store 或学生业务类型。
- **两套宿主适配器**：分别把宿主路由、菜单、身份上下文、请求封装、组件库及生命周期映射到统一契约。Vue composable 与组件留在 Vue 实现层，不放进框架无关协议。
- **业务页面与插件配置**：学生名单、模拟考试等声明页面和业务能力，保留各自领域校验；不直接访问宿主内部路由、store、原始令牌或数据库。

抽取现有共享代码时，先区分通用请求与会话语义、Vue 实现、school 业务三部分。不能只把 school bridge 改名，就视为完成框架解耦。宿主可复用自己的组件样式，但字段、校验、事件和错误语义应一致，不要求两套 UI 像素一致。

### 10.4 前端适配契约建议

以下是建议的契约分组和示意名称，不是当前已存在的 API；实现时应形成版本化接口定义、Schema、错误字典与可执行示例。

| 契约组 | 适配器应实现的职责 | 必须保留的边界 |
| --- | --- | --- |
| transport.invoke | 按 capabilityId 发起调用，统一响应、错误、超时、取消和追踪信息 | 请求鉴权由可信宿主层处理；插件不能指定任意带凭据 URL；服务端重新鉴权 |
| context.get / subscribe | 提供当前用户、租户、语言与必要权限视图，通知上下文变化 | 只提供必要信息，不暴露原始令牌；前端上下文不是服务端授权依据 |
| pages.register / unregister | 将页面描述映射为命名空间内的路由、菜单、标题、布局与直达链接 | 路由冲突拒绝；菜单隐藏不代替鉴权；刷新能恢复合法页面 |
| slots.register / mount / unmount | 声明宿主槽位，将插件配置挂载到允许位置并释放资源 | 明确 slotId、输入输出 Schema、组件类别与排序；不允许任意 DOM 修改 |
| renderer.render | 把框架无关页面配置渲染为宿主组件，统一字段、校验及事件语义 | 仅允许白名单组件与声明事件；不执行配置中的任意脚本 |
| lifecycle.applyRevision / dispose | 应用目录版本、撤销失效入口、释放订阅与组件，处理未保存表单 | 服务端停用先阻断调用；迟到清单不得恢复已撤销入口 |

主题、通知、国际化等可以作为可选扩展能力；不得让缺少可选能力悄悄变成安全降级。槽位不存在时明确拒绝挂载并说明原因。业务页面需要新槽位，应由宿主开发者显式增加和发布，插件不能自行扩大可访问区域。

### 10.5 版本与身份约束

**设计建议**：适配器声明自身版本、支持的契约版本范围、页面 Schema 版本、组件及槽位能力列表；插件声明所需版本和必需能力。宿主与插件协议、Schema、插件版本和 UI catalog revision 分别管理，不混用一个版本号。缺少必需能力或版本不兼容时，不发布该页面/槽位，并显示可定位的原因，不加载半兼容页面。

登录失效、退出登录、租户切换或权限撤销时，清理相关页面状态、缓存和在途订阅，重新取得有效清单；不能把上一租户的内容复用于新租户。统一错误应区分未认证、无权限、插件停用、版本过期、能力缺失及业务校验失败。配置中的调用权限与服务端身份、插件授权和租户范围共同生效。

可信同源壳的会话整合由宿主适配层完成，不向插件配置暴露令牌。未来跨域或开发式页面需单独设计身份传递与隔离，不继承当前 localStorage 共享假设。具体会话存储改造需独立评估，不在本次设计追加中声称已更换认证实现。

### 10.6 两套适配的交付与后续 UI 接入

**设计建议的首期交付**：通用契约与 Schema；plus-ui 和 soybean 各自的适配实现及固定版本说明；接入步骤与改造点清单；同一个配置插件样例；同一套契约测试和两套前端的独立验收记录。

新 UI 接入按“声明支持版本与能力 → 实现适配器 → 接入启动入口与页面容器 → 显式提供槽位 → 运行契约测试”进行。最小改动集中在请求、认证上下文、菜单路由、渲染器、槽位与资源清理，不要求重写既有业务；但不承诺完全零改造。初次接入或增加宿主槽位可能需要构建和发布宿主前端；适配完成后，符合现有契约和组件集的新配置插件才要求无需前端重建即可生效。

两套现有 Vue 前端通过验收，证明的是两种壳的适配成立。后续建议增加一个最小 React 宿主，使用同一份配置插件和同一套契约测试，验证框架无关边界；React 适配不列入首期已确认交付，不要求复用 Vue 组件源码，也不能仅凭接口定义声称已支持 React。

## 11 统一导入导出

### 11.1 职责分工

- 连接器：与文件、测试 API 或后续外部系统通信，负责读取或投递。
- 格式适配器：解析/序列化、字段映射、格式标准化，不决定业务权限与覆盖规则。
- 业务处理器：学生字段语义、唯一性、校区班级关系、冲突处理、业务写入与事件。
- FCP 流水线：权限、配置版本、校验、预览、确认、任务、幂等、检查点、审计和统计。

“后续导入自动继承”指实现这些契约并注册到统一流水线的新入口自动获得治理，不是自动拦截所有旧接口、数据库写入或第三方软件。

### 11.2 人工导入

创建任务 → 固定输入摘要与映射版本 → 解析和标准化 → 领域校验 → 展示成功/失败/冲突预览 → 用户确认处理策略 → 再校验授权、版本和业务冲突 → 按已声明事务粒度写入 → 返回可追踪结果。

预览不是锁住全库。预览后业务数据变化，应报告冲突或要求重新预览，不能用旧预览静默覆盖。事务粒度可为整个批次或每条/每批，但必须由领域处理器声明、UI 显示并被测试，不承诺跨远程服务整体事务。

### 11.3 自动导入

使用预先授权的固定配置和任务身份，保存输入来源、适配版本、冲突策略与事务粒度。超出策略的异常进入待处理，不自行作新的业务决策。连接器重试和业务提交去重分开，源游标与已提交检查点需保证不会静默丢数据。

### 11.4 导出

提交任务时校验导出权限、字段范围与数据范围；生成时和下载时再次检查必要权限及有效性。文件放私有存储，下载地址有受控授权与有效期，不用公开永久 URL。格式选择后补公式注入等专项防护。

临时输入、导出文件、任务明细、安装缓存的保留周期尚未确认，应与业务数据 del=1 政策分开配置。到期清理不能删除插件业务记录。首期不自动向外部目的端投递，后续按具体数据和目的端授权。

## 12 本地与远程以及宿主替换

本地 ProcessProvider 与远程 Provider 共用调用、授权、依赖、错误和生命周期外观，但承诺不同：本地可以管理已授权子进程；远程注册只控制 FCP 的访问与路由，不拥有远端部署权。

远程第一阶段建议 HTTP JSON 契约，是否需要 gRPC 由真实性能和流式场景决定。必须有 TLS、服务身份、凭据引用、超时、连接限额、健康与幂等；登记 URL 需要 SSRF 防护、允许目标规则、重定向和 DNS 重解析控制。合法内部地址可以按明确策略登记，不能无条件封禁所有内网也不能无条件放行。

部署适配器若后续接入容器或编排平台，应独立声明“发布、停止、回滚”的权限与目标，登记服务地址本身不授予部署权限。共享服务的消费者范围必须可见。

宿主替换应按能力逐项验收，而不是替换一个 JAR 名称：身份与租户语义、权限与数据范围、存储事务、审计事件、文件下载、任务身份、UI 壳契约都要映射。某宿主缺失的能力由独立能力提供者补齐或明确不可用，不由核心静默降级为无权限运行。

## 13 开发环境与后续能力

轻量开发宿主需要可运行入口、受限开发身份、示例租户、配置存储、插件管理 API 和前端演示壳。开发认证必须显式开启，并在生产配置拒绝启动；不能把无认证控制台直接暴露为生产 API。

真实 RuoYi 源码集成环境继续验证登录、验证码、租户、RBAC、数据权限和 UI 集成。现有核心独立构建产物不等于完整开发宿主。宿主无重启插件安装必须在真实 RuoYi 环境验证，不能只用假宿主证明。

生产基础能力以可扩展能力提供者接入：日志与审计、监控与告警、组织租户、文件、消息、任务、备份恢复、发布灰度、配置运维、流程。首期必须包含与本次闭环直接相关的安全、可观测、恢复和审计；其他能力按实际需求逐步补齐。

AI 放在后续能力扩展：模型 API、凭据、配额、路由与审计；MCP 工具注册与授权；Skills 版本资产和执行绑定。接入现成中台可以减少重复建设，但当前没有已选定的中台产品。Skills 注册不等于自动具备安全执行能力。

## 14 实施顺序与交付门槛

1. **基线和契约**：固定源码版本、行为测试；落 manifest、能力、调用、存储和 UI Schema，建立契约测试。先从现有 Engine/Registry 扩展，避免平行重写一套生命周期。
2. **安装和恢复**：可信包安装、不可变目录、持久目录、操作状态机、CAS 发布、启停排空、重启恢复。
3. **权限和存储**：RuoYi 适配下沉、任务身份、受控存储、结构迁移、逻辑删除与恢复检查。
4. **前端和数据交换**：完成 plus-ui 与 soybean 的固定适配、通用接入契约和改造说明；同一配置插件在两套 UI 中分别验收配置页与槽位；学生名单文件输入、测试 API 输入、文件导出，预览和冲突处理。
5. **真实验收**：在轻量宿主与 RuoYi 两种环境跑同一业务契约、故障注入和权限测试，记录具体提交和配置。
6. **扩展验证**：模拟考试第二插件；随后远程注册、第二真实宿主、开发式前端、多实例与独立数据库，分别设验收门槛。

不能把“目录创建完成”“接口编译通过”“开发宿主能跑”当作生产就绪。每阶段输出实际日志、测试结果、版本摘要和已知限制。

## 15 可执行验收清单

执行前准备：固定宿主/FCP/插件提交与摘要；创建租户 T1、T2 及各自管理员、普通用户和任务身份；准备插件 P、依赖插件 D、冲突版本 D2；准备学生输入的正常、重复、跨校区、错误、超限、授权不足样本。实际格式选定后再生成 Excel/CSV 专项样本。准备可阻塞、可取消、提交后故意断连的测试操作，以及在指定检查点终止进程的故障注入开关。

所有测试使用测试数据和隔离环境；不得在生产中直接执行杀进程或破坏性故障注入。下表是待执行测试，不是 PASS 报告。

| 编号 | 操作与故障注入 | 通过条件与证据 |

| A01 | 启动宿主，记录 PID；安装新 P 并启用 | 无构建宿主、无重启；PID 不变，业务端点与 UI 可用，包摘要及操作日志完整 |
| A02 | 提交不兼容契约、重复 ID、路径穿越、超大解压、错误摘要包 | 拒绝安装/启用，无目录越界或覆盖，无可调用半成品 |

| A15 | 插件连续崩溃，宿主重启，模拟 PID 重用 | 调用拒绝与告警可见；重启有预算；不误杀其他进程；持久意图恢复正确 |

| A17 | 两个兼容版本升级并尝试回退 | 宿主不重启；插件停机窗口明确；只回退到结构兼容版本 |

| A30 | 批次中途失败并恢复，重复投递相同源记录 | 已提交项不重复；未提交项可识别；源游标不会跳过未完成数据 |

| A38 | 两套 UI 分别直接打开插件深链、刷新页面，并从另一浏览器启停插件 | 当前清单正确恢复；会话按版本收敛；无重复路由/菜单，停用后的深链不恢复可操作页面 |
| A39 | 两套 UI 分别切换租户、退出/过期登录、撤销权限，同时保留旧页面或在途请求 | 不泄漏上一身份的数据；缓存与订阅清理；旧页面提交由服务端拒绝；错误可区分 |
| A40 | 提交不兼容契约/Schema、缺少必需组件、未声明槽位和冲突路由 | 拒绝对应页面/挂载并指出原因；不静默降级，不影响其他页面或扩大权限 |
| A41 | 对两套 UI 做接入依赖检查，并核对公开适配说明 | 通用协议无 Vue/React/宿主 store/学生领域依赖；壳差异集中在适配器；配置插件不引用宿主内部实现，说明列出所有实际改造点 |

后续能力单独验收，不阻塞首期但不能提前标支持：
- R01 远程注册与调用：停用只撤销 FCP 路由；服务共享消费者不受误停；断连、超时、未知提交正确处理。
- R02 远程目标安全：非法地址、重定向、DNS 改变、错误服务证书及过期身份按策略拒绝。
- R03 授权部署适配器：操作目标、操作者、版本与回滚范围可追踪，登记地址不自动获得部署权。
- H01 第二真实宿主：替换宿主实现后，通过身份、租户、权限、数据、审计和 UI 契约测试，不修改业务插件。
- M01 多实例：停用/升级广播延迟、旧 generation 拒绝、节点分区、故障节点恢复、调度去重全部实测。
- D01 独立数据库：事务边界明确，事件至少一次与消费者去重，跨库失败补偿与核对可操作。
- U01 开发式前端：资源版本、隔离、CSP/来源策略、数据访问、卸载清理及恶意组件测试。
- U02 React 最小宿主适配：同一配置插件通过 A37–A41 对应契约场景；无需修改通用协议或业务配置来迁就 Vue 依赖；记录新增适配代码与能力差异。该项是后续建议，不作为首期已支持 React 的声明。

性能测试需记录包大小、并发、数据量、硬件、数据库和语言运行时；测量启停耗时、排空耗时、调用开销、内存、吞吐及错误率。没有明确业务目标前不凭空填“毫秒启用”“零损耗”等通过阈值。生产就绪另需容量、长稳、灾备恢复、依赖故障和安全评审。

## 16 实施前仍需明确的项目参数

这些参数不改变已确认架构，也不要求重新逐项选择总体方案：
1. 学生名单首期文件格式：Excel 或 CSV，当前未确认。
2. 学生唯一标识、必填字段、校区与班级关系、重复数据默认处理策略和批次事务粒度：由具体领域需求确定，不从框架设计猜测。
3. 排空超时、重试预算、任务并发、包大小和导出有效期等运行参数：先提供显式可配置值，在验收环境校准。
4. 临时文件、任务明细和安装缓存的保留周期，与业务数据不硬删除分开决定。
5. 首期插件进程隔离强度和共享方式，应在安全/资源评估后落配置；若仅可信同用户进程，须写明限制。
