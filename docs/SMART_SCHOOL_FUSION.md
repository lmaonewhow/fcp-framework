# 智慧云校融合基线

此基线合入四个模块的完整增量：生成器 PR12 `984bdd7`、品牌 PR13 `6492573`、教育基础资料 PR14 `0c80896`、教育关系名册 PR15 `bc1b046`。PR15 已包含 PR14。融合不等于远端 PR 已合并，也不代表生产部署。

双端品牌、原生登录、许可证和精确菜单清理保持原样。教育基础资料与名册目前位于管理端 `/admin/fcp/education`、`/admin/fcp/roster`，按各自独立权限和学校范围提供能力；教师端品牌已融合，不宣称这些管理端业务页面已出现在教师端侧栏。原 PR14/15 页面是手写专用业务实现，不是 PR12 普通生成器产物。此融合新增固定 `education-p042-v1`：完整核验仓库 P042 DDL/model 后，结合已审规则，真正生成并安全应用两组页面、字段/API 定义、溯源清单和服务端路由，共 10 个文件。旧页面已明确转为模板；可信身份、事务、权限、状态约束及请求结果处理仍是手工维护的业务内核。它不是任意 SQL 的万能 CRUD，也未开放名册写入。

同一源码及宿主的验收入口可以使用 `python tools/ci_native.py --ingestion --education --roster --generator`。品牌检查在所有业务模块后执行，并保留完整原生租户列表限流窗口。普通生成业务的 `--generator-business` 会重构 JAR 和替换测试宿主，因此暂时拒绝与教育/名册模式同时开启：教育许可与配置绑定原始 JAR 摘要，未经按最终产物重新建立计划和隔离许可，不能把旧摘要用于新宿主。这个 guard 不关闭摘要校验，专用教育 SQL 链路在构建前完成生成和安全应用，再从该精确源码 clone 构建一次真实 JAR，并把最终 buildId/JAR SHA 绑定到教育许可；不会在绑定后替换宿主。

本地组装和组件通过不等于真实 MySQL、加密登录或浏览器验收。最终结果必须绑定新的组合提交、JAR 摘要和实际运行证据，不复用各独立 PR 的 PASS 作为融合通过。既有库、用户电脑和生产环境不在本次执行范围。

## 教育 SQL 生成的验收闭环

`.github/workflows/native-generated-school.yml` 在独立无硬链接的精确提交 clone 中调用真正 Java renderer，先核对全部 10 个受跟踪输出，再仅移除这些已核对文件并通过同一 `GeneratedSourceWorkspace` 生成 CREATE 计划、确认落盘。输出必须逐字节回到提交快照且工作区干净；随后所有组件、前后端构建和原生验收均从这个生成后的 clone 执行。

运行顺序为基础宿主、基础资料、名册、普通生成器安全应用、教育生成器 Web 流程、最终双端品牌检查。`--education-generator` 需要 `--ingestion --education --roster --generator` 四个前置开关；没有同源 prebuild receipt 会在任何数据库写入前失败。真实 Web 写入使用另一个 CI 专用开发工作区，输出 SHA 与构建前源码逐项一致，不冒充点击应用后热加载正在运行的 JAR。

生成模式支持学校/组织/班级的受限新建与名称 CAS；学期、学籍、入班、任教关系仍只读，人员展示策略 PENDING。SQL 全 54 表经过结构验证不等于 54 表页面或全 CRUD 已完成。删除、状态转换、身份绑定、其余领域命令和生产发布仍未开放。界面快速调整使用不在生成清单的 `customization.ts`；生成文件也受基线/手改/双边冲突保护。新 clone 可在文件等于真实候选时明确登记基线，绝不强制接管不同内容。
