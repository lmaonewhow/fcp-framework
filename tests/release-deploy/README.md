# Local process release executor

`LocalProcessDeploymentProvider` is a concrete, opt-in Linux single-controller executor for trusted services that implement the explicit health protocol below. It is not an arbitrary RuoYi JAR deployer, a production process supervisor, or an untrusted plugin sandbox.

The deployment owner supplies fixed `ServiceSpec` registrations: system release ID and manifest digest, artifact path and SHA-256, absolute executable and argument vector containing `{artifact}`, dedicated numeric loopback origin, and exact allowed business paths. Release API callers cannot supply commands, addresses or environment variables. The executor copies verified artifact bytes into an owner-private temporary snapshot and launches that snapshot. Runtime binaries, additional classpath/dependencies and the registered command remain trusted deployment prerequisites; a digest verifies integrity, not publisher trust.

The constructor accepts a dedicated durable `StateJournal`, `DurableReleaseRouter`, registrations, environment, clock and backend identity key. Production key provisioning remains the deployer's responsibility; no credentials are persisted by this module. The fixture uses a clearly public synthetic key.

Services receive only `LANG`, `FCP_RELEASE_ID`, `FCP_RELEASE_DIGEST`, `FCP_RELEASE_INSTANCE` and `FCP_RELEASE_PORT`. `GET /fcp/health` must return exactly `releaseId`, `manifestDigest`, `instanceId`, `pid`. Readiness checks compare the recorded PID and process start instant, random instance identifier, release ID and manifest digest. An occupied endpoint is rejected rather than adopting another process. Health bodies and time are bounded.

`DEPLOY` launches stable and candidate services, verifies both, and initializes routing. `CANARY`, `EXPAND`, `PAUSE`, `PROMOTE`, `ABORT` and `ROLLBACK` change actual router policy. ABORT invalidates affinity and disables all governed ingress. It does not route traffic to the old version, require the service registry, or require either process to be healthy. ROLLBACK is a separate compatibility-preflighted operation: it reopens ingress on the healthy stable service, so a failed candidate cannot block that verified recovery. Operation intents, process identities and receipts persist before effects; duplicate operations do not relaunch. Recovery checks live process identity. A crash after routing and before receipt can be reconciled only when the exact expected router revision/epoch matches. A crash between process creation and identity persistence remains explicitly unresolved, never guessed or blindly relaunched.

`invoke` performs real requests through the shared signed-context transport. Its in-flight count includes requests made through this executor instance only; it cannot prove global task or request drain after controller restart. Consequently **RETIRE is unsupported**. There is no automatic forced kill, application task cancellation or database rollback. `stopOwnedProcesses` is explicit development/test cleanup: it refuses local active requests and stops only ProcessHandles created by that object. It does not adopt/kill persisted PIDs after reconstruction. Generated artifact snapshots are removed only after confirmed termination; crash leftovers are not automatically deleted.

Run `source /workspace/shared/fcp-toolchain/env.sh && bash tests/release-deploy/run.sh` when that local toolchain exists, or use any JDK 17+ and Python 3. The tests start two real Python child HTTP services, verify actual stable/candidate/rollback response bodies and backend signed identity, idempotent deployment, process identity recovery, failed-candidate rollback, occupied-endpoint refusal, artifact digest rejection and honest unsupported retirement. Tests are not native RuoYi, MySQL, browser, external cloud or production acceptance.

Safe recovery uses the non-expiring local operation ledger and canonical command digest. `supportsRecovery()` is true; `recovery(command)` returns `NOT_ACCEPTED` only for the valid next generation when no conflicting unresolved claim exists. An existing exact receipt is `ACCEPTED` even if startup or route execution failed; it is never converted to absence. Digest mismatch fails closed. `resumeNotAccepted` performs the same durable CAS claim as submit before any process or routing effect; exact duplicates do not execute again. `supportsFencedContainment()` remains false because this executor does not claim distributed delayed-command fencing.

The recovery regression injects failure after the controller persists its intent but before executor submit, closes/reopens the controller journal, reconstructs the controller, and safely resumes via authoritative absence. It then verifies actual two-process readiness and routing. This is a durable journal/controller reconstruction test, not a claim of an OS crash or a second JVM. Accepted-but-unresolved startup remains pending without reexecution, and another command cannot claim its generation.

Containment regression promotes to FULL, makes compatibility/registry preflight unavailable, reconstructs an executor without service registrations, and executes ABORT. It checks the actual router is disabled, the observation is STOPPED with exact generation/digest, both GET and POST are rejected, and neither process receives additional business requests. An attempted ROLLBACK while preflight is unavailable leaves ingress closed; restoring preflight allows an explicit rollback, not automatic traffic reopening. ABORT does not claim cancellation of requests already admitted before the stop.

Known pre-route failure is distinct from an uncertain launch. For non-DEPLOY actions, failed readiness checks occur before any route mutation and are persisted as terminal FAILED receipts with the exact command digest, consumed operation generation and unchanged actual routing mode/proportion. Observations use typed `ExecutionOutcome.FAILED`; health alone does not define execution success. The controller can reconcile to FAILED and issue a subsequent ABORT. Exact failed-command replay never executes again. DEPLOY failures that may include process-launch effects remain unresolved rather than being silently retried or declared effect-free. Regression tests kill the real candidate during CANARY, exercise both PAUSE and EXPAND readiness failure, verify unchanged route revision and terminal controller state, then prove ABORT closes actual ingress.
