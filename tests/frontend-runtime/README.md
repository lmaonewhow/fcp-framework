# Frontend runtime verification

Run `tests/frontend-runtime/verify.sh` with TypeScript on PATH or `TSC=/absolute/path/to/tsc`. It strictly compiles the framework-neutral implementation and runs the 15 Node contract tests. One group executes all 27 entries in the shared Java/frontend boundary corpus; those are not 27 additional independent integration scenarios.

Run `tests/frontend-runtime/verify-host.sh` with JDK 17+ and TypeScript to compile the actual core/business/host Java sources and check 14 bounded route-policy assertions plus 24 shared-session assertions. Its HTTP response is an explicit test double.

After native dependencies have been installed, run `node tests/frontend-runtime/verify-vue-host.mjs <assembled frontend directory>`. The four tests use that frontend's actual Vue/Vue Router, a custom renderer, and an explicit transport double. They cover both host adapter modes, initial deep links, identity cleanup, stale requests, unsaved edits, explicit same-key retries, blocked input changes while pending, abandonment, and unmount. This is not a browser/login test. The recorded run executes it independently with both native dependency installations.

Actual pinned-host builds are recorded separately under `evidence/native/`, copied from `/workspace/shared/fcp-native-ui/reports`. They use original frontend dependencies, the reviewed admin lockfile, upstream frozen soybean lockfile, the existing native build/typecheck commands and real components/stores. No authentication bypass or fake native session is used to claim native acceptance. The first soybean typecheck failed because an unused manual-route locale key did not belong to Elegant's generated route-key type; the fix removes that extra key rather than weakening the check. The original failure log is retained.

The isolated `context-key-order-before-fix.log` restores only the old identity comparator in a temporary source copy to demonstrate the regression; two tests fail as expected. The fixed implementation normalizes identity key order and permission ordering; final Vue tests pass. This reproduction does not modify the tracked source or native projects.

Native browser interactions, authenticated backend calls, database authorization, simultaneous browsers and measured convergence delay are NOT_RUN by this suite. The configured poll interval is five seconds and must not be reported as a measured end-to-end update time. Unknown-result retry information is deliberately memory-only and not persisted after reload.

Administrator management tests use `node tests/frontend-runtime/verify-vue-host.mjs <assembled frontend directory> manager`. The 17 Vue tests cover permission gates, platform-only installation, SHA-256/explicit upload consent, no implicit grant/enable, byte-identical retry, exact cascade confirmation, explicit drain cancellation, no blind replay of unknown decisions, identity cleanup, manifest-based grant choices, scope confirmation, server-context changes, server-authorized native wildcard compatibility and explicit retained-data uninstall with query-only unknown-outcome recovery. They use explicit service doubles and are not claims that a real signed package was installed or a database grant was written. Both native builds/typechecks are rerun after management UI changes, and pre-management build evidence is retained separately.
