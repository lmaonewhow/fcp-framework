# 迁移、部署与复测手册

## 本地复测

解压后在包根目录使用Python 3.11或更高版本、Node 20或更高版本运行下方命令。本地路径不需要pip或npm安装依赖，不需要-X utf8；测试只操作临时SQLite文件和当前输出目录，不连接学校数据库、不启动FCP。实际本次Python与Node版本见原始证据。

```text
python tools/run_checks.py --output evidence/my_local_run
```

输出包含结构化汇总、逐测试状态、Python日志、Node日志和被测源码摘要。Node不存在时记录NOT_RUN并使整体检查不通过。不要使用python -O；不要带EDU_MYSQL_TEST_SCHEMA运行本地入口，工具会拒绝，以避免意外切换到原生连接模式。日志文件始终UTF-8，控制台JSON使用ASCII转义，中文Windows不依赖系统默认文本编码。

本包还记录关闭UTF-8模式并使用GBK输出的Linux子进程复测，以及中文路径运行。它们是可移植性参考证据，没有冒充原生Windows验收。Windows原生必须在实际版本、终端、路径和权限下执行同一入口，并保留运行环境。

## 真实MySQL入口

先准备经团队批准并固定到精确补丁的MySQL 8.4测试实例，以及锁定版本的PyMySQL依赖。安装依赖属于使用方受控工具链，本包没有联网下载它，也没有提供未经核验的依赖哈希。测试用户只能操作fcp_design_verify_前缀的隔离库；生产凭证不得用于这个入口。连接限定127.0.0.1，端口来自EDU_MYSQL_PORT，用户和密码从EDU_MYSQL_USER与EDU_MYSQL_PASSWORD取得，日志不输出密码。

```text
python tools/mysql_acceptance.py --expected-version 8.4.<已批准的实际补丁> --provision-isolated --output evidence/my_native_mysql
```

命令中的版本占位必须换成实际精确版本。工具检查版本与产品身份，创建自己的随机库，执行当前生成DDL，检查表与外键数量，再执行同一批关系约束用例、NO PAD与UTC检查以及真实双连接共享锁/撤销顺序实验。仅删除本次成功创建的随机库；--keep-schema保留该测试库供诊断。没有指定开关、缺少驱动或凭证时明确NOT_RUN。

这个原生入口尚未在本环境执行到建库阶段，因此是待验证的验收工具。PyMySQL解析、目标服务配置或MySQL行为可能暴露新的问题，不能跳过失败。测试中使用断言，工具主动拒绝优化模式；生成SQL解析器只支持本包简单语法，不作为通用SQL迁移解析器使用。

## 从已有FCP渐进升级

先读取实际数据库的迁移记录、表结构、排序规则、当前数据、应用版本和插件配置。模型中的旧提交与V001至V004是沿用上次交付的来源信息，本轮没有重新访问当前仓库，不能据此假设某个安装库已经执行那些版本。

扩展阶段新增兼容字段和表，维持旧读路径。回填阶段按源版本与稳定ID生成映射，记录每个批次摘要、游标、失败行和已提交数量。学籍、学期、班级名称或字符串历史键存在歧义时进入隔离队列，必须确认后再关联；身份键冲突、UTF-8问题和超长引用不通过截断掩盖。

新旧数据并行核对使用冻结来源或可靠提交快照，检查关键业务结果、对象关系、指标版本、用途投影和附件摘要。重复回填不得重复记账或发通知。切换前冻结或协调相关写入，确认最后增量与回执，再切换当前读写绑定；控制面期望与执行端确认不同步时维持未完成状态。

收缩阶段只在旧客户端、旧任务和旧应用兼容窗口结束之后移除旧结构。回退优先切回仍兼容的代码与配置；不可逆数据转换采用经演练的前向修复或恢复流程。MySQL原子DDL不等于多个DDL步骤或业务迁移整体可回滚。[S11]

## 部署责任与运行账号

数据库迁移账号与运行账号分离，应用账号没有DDL权限；不可变事实表优先授予插入和读取，当前指针、队列状态等必要可变表单独授权。合法保留和删除使用独立审查路径。受限查询只读账号仍不提供MySQL原生行级租户隔离，必须经过可信服务端范围过滤；更强隔离需求采用独立库或部署实例。

连接池为每条新物理连接设置UTC和经批准的SQL模式。启动只检查期望结构、必要约束和兼容版本，缺项时准确失败，不用临时文件库假装启动成功。Python工作进程尽量通过Java能力接口访问数据，不获得跨领域全库写账号。

备份覆盖正式数据、对象附件、配置/规则、发布manifest及必要密钥依赖。恢复演练同时验证历史评价、更正头、去重墓碑、插件启停与未决外部动作，防止恢复后重复发放。RPO/RTO必须由真实环境测得并由项目批准，本包没有给出未经验证的分钟级承诺。

## 最终发布检查

填入真实manifest和真实产物，再由保护环境产生生产证据，使用下方入口检查。现有NOT_BUILT/NOT_RUN模板执行时返回阻断是预期行为，不能作为生产验收已通过的证据。

```text
python tools/release_gate.py contracts/production-evidence.NOT_RUN.json --manifest contracts/release-manifest.NOT_BUILT.json --artifacts artifacts --expected-db-version 8.4.<实际补丁>
```

该命令只检查证据完整性，不部署、不改路由、不授予权限。任何未执行项、跳过项、摘要变化、假退出码、日志缺失或不兼容产物，都应先回到相应验收步骤。设计包交付不等于学校生产环境已经上线。

## 4.2复测证据接收规则

本地运行先锁定输出目录，再以新run_id写入RUNNING和invocation.json。正常结束保存completed、exit_code、唯一测试ID摘要和源码摘要；超时为ERROR，用户中断为INTERRUPTED。硬终止可能留下RUNNING与残留锁，任何这些状态都不能自动放量。读取者必须校验本次进程退出码和本次run_id，不能仅看一个文件里的PASS。文件原子替换减少半写JSON，不承诺存储介质损坏或断电后的全盘持久性。

每次原生MySQL与CI运行使用新的独立输出目录，绑定该次CI作业标识，不复用历史结果路径。原生入口虽然提供了同批关系测试和4.2新增关系用例，仍须先在目标MySQL上验证工具本身。异常、超时或未执行时不能继承旧目录中的任何证据。

从P041设计迁移到P042，需要审查当前账户的多重有效关系、执行许可的作用域来源及历史授权。不要根据存在的班级自动为所有学校开通许可。账户冲突进入人工队列，确认后的当前指针与授权epoch同时切换；class_id可空的读路径要复核现有统计是否错误使用INNER JOIN过滤无班级事实。新SQL仅用于全新隔离库，现有库仍需单独生成并审查迁移。

## 4.2.1：原生入口的失败语义

本补丁不改model.json与P042建表SQL。read查询Q042及工具有变化，部署这些代码前仍须与实际宿主适配并验收；不需要因本次补丁虚构P043迁移。已有旧库仍不能直接运行P042。

MySQL连接在创建后统一设置UTC、严格SQL模式、外键检查及REPEATABLE READ，并读回验证。任何初始化失败使测试失败。负向关系测试只捕获明确约束码1048、1062、1451、1452、3819；连接丢失、超时、死锁、未知列与语法错误必须作为异常。原生行结果在适配层规范为列表，保留行元组和列值。

原生运行也生成run_id、输出目录锁与RUNNING记录；同一输出目录不可并行运行。输入读取失败、异常和中断会写入本次ERROR或INTERRUPTED；硬终止可能留下RUNNING及锁，不能当成成功。判定必须核验实际进程退出码、本次run_id和完成状态。当前NOT_RUN证据仅表明前置条件不足，没有连接服务器。
